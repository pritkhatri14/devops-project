🛠 Troubleshooting Center

Identify common DevOps problems, understand their causes, and follow practical steps to investigate them.
Before troubleshooting: These are general guides, not automatic diagnoses of your computer. Read each command before running it. Commands such as stopping or deleting containers can interrupt services, so investigate first.

JENKINS

01. Jenkins Pipeline Failed

Possible cause: A test failed, a file is missing, or a pipeline command returned an error.

First investigation command

sudo systemctl status jenkins

Steps to investigate

  1. Open Jenkins at http://localhost:8080/.
  2. Open the devops-project job.
  3. Open the failed build and select Console Output.
  4. Find the first meaningful error in the log.
  5. Correct the cause, then run the build again.

Remember: The console log helps identify which pipeline stage failed.

DOCKER

02. Container Is Not Running

Possible cause: The application exited or the container encountered a startup error.

First investigation command

docker ps -a

Steps to investigate

  1. Find the container name in the command output.
  2. Check whether its status is Exited.
  3. Inspect its recent logs.
  4. Check the image and port configuration.
docker logs --tail 50 CONTAINER_NAME

Replace CONTAINER_NAME with the actual container name. Logs can reveal why the application stopped.

WEBSITE / HTTP

03. Website Shows Unable to Connect

Possible cause: The container is stopped, the port mapping is wrong, or the service is unavailable.

First investigation command

curl -I --max-time 3 http://localhost:8085

Steps to investigate

  1. Check whether the expected container is running.
  2. Verify the host-to-container port mapping.
  3. Check whether another process is using the port.
  4. Inspect the container logs if the problem continues.
docker ps sudo ss -ltnp | grep ':8085'

A successful HTTP response such as 200 indicates that the web server responded to the request.

DOCKER

04. Docker Permission Denied

Possible cause: The current user does not have permission to access the Docker socket.

First investigation command

docker ps

Steps to investigate

  1. Read the complete permission error.
  2. Check whether the Docker service is running.
  3. Check the user's Docker access permissions.
  4. Follow your system administrator's approved permission setup.
sudo systemctl status docker

Do not change socket permissions to 777. Docker access can grant powerful control over the host computer.

LINUX

05. Disk Space Is Low

Possible cause: Logs, downloaded files, Docker images, or other files are consuming disk space.

First investigation command

df -h

Steps to investigate

  1. Check the Use% column in the output.
  2. Identify which filesystem is nearly full.
  3. Inspect Docker disk usage if relevant.
  4. Review files before deciding what can be removed.
docker system df

Avoid pruning Docker resources until you understand which images, containers, and volumes your project needs.

WEBSITE / HTTP

06. HTTP 404 Not Found

Possible cause: The requested page or resource does not exist at that URL.

First investigation command

curl -I http://localhost:8085/

Steps to investigate

  1. Check the URL and requested file path.
  2. Confirm the HTML file exists.
  3. Verify that the file is mounted into the expected Nginx directory.
  4. Check the web server logs for further details.
docker logs --tail 50 devops-error-center

HTTP 404 means the server could not find the requested resource. It does not necessarily mean the server is down.
